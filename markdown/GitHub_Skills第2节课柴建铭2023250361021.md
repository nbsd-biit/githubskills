## 一、核心知识点梳理

本节课学习 Markdown 的基本语法和在 GitHub 中的使用方式。Markdown 是一种轻量级标记语言，常用于 README、Issue、Pull Request 描述、项目文档和实验报告编写。核心知识包括标题层级、段落、加粗、斜体、列表、引用、代码块、链接、图片、表格和任务清单等。

标题层级使用 # 号表示，能够让文档结构清晰；列表适合整理步骤和要点；代码块可以保留代码缩进并进行语法高亮；链接和图片可以补充外部资料和运行截图；表格适合展示实验环境、问题记录和解决方案。Markdown 的优势在于语法简单、可读性强，即使不导出成 PDF，也能直接从源文件中看出内容结构。

## 二、学习中的难点

学习中的难点主要是标题层级和代码块格式。标题如果随意使用，会导致文档层次混乱，影响阅读体验，也会影响后续导出 PDF 时的目录结构。代码块如果没有使用三个反引号包裹，容易出现缩进丢失、特殊符号被解析、代码和正文混在一起等问题。

另一个难点是图片路径问题。在本地 Typora 中插入图片后，如果图片路径使用了电脑上的绝对路径，上传或移动文件后可能出现图片丢失。因此 Markdown 文档最好使用相对路径，并把图片和文档放在同一个项目目录中统一管理。

## 三、实践操作与收获

实践过程中，我在练习仓库中编辑 Markdown 文件，分别使用一级标题、二级标题、无序列表、有序列表、任务清单、表格和代码块组织内容。我尝试将学习步骤写成任务清单，将命令和代码写入代码块，并用表格整理 Markdown 语法与作用。完成修改后提交到仓库，并观察 GitHub 页面中 Markdown 的渲染效果。

通过这次操作，我认识到 Markdown 不只是“写字”，更是一种规范化表达方式。好的 Markdown 文档应该让读者能够快速看清标题结构、重点内容和操作步骤。对于课程实验报告来说，Markdown 可以帮助我把核心知识点、难点、实践过程和疑问分成清晰的模块；对于软件工程项目来说，README 能够帮助别人快速理解项目用途、运行环境、安装步骤和常见问题。

## 四、学习遇到的困惑与疑问（选做）
