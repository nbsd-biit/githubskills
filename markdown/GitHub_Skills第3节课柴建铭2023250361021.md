## 一、核心知识点梳理

本节课学习 GitHub Pages 的基本使用方法。GitHub Pages 可以把仓库中的静态网页文件发布成可访问的网站，常用于个人主页、项目展示页、课程作业展示页和技术文档页面。核心知识包括静态网页、仓库设置、发布来源、分支选择、index.html 文件和页面访问地址。

GitHub Pages 的基本逻辑是：在仓库中准备网页文件，例如 index.html、CSS 文件和图片资源；在仓库 Settings 中启用 Pages；选择发布分支和目录；等待构建完成后，通过 GitHub 提供的网址访问页面。它适合发布不依赖后端服务器的静态内容，如果网页只包含 HTML、CSS、JavaScript 和图片资源，就可以直接托管。

## 二、学习中的难点

学习中的难点是区分“仓库文件已经提交”和“网页已经成功发布”。文件提交到仓库并不代表页面马上可以访问，还需要正确配置 Pages 的发布来源，并等待系统完成构建。另一个难点是首页文件命名，GitHub Pages 默认会寻找 index.html 或相应的入口文件，如果入口文件缺失或路径错误，访问页面时可能出现 404。

此外，静态资源路径也容易出错。例如 HTML 中引用图片或 CSS 文件时，如果路径大小写不一致，或者文件夹层级写错，本地可能能打开，但发布到网页后会出现样式丢失或图片无法显示。

## 三、实践操作与收获

实践过程中，我按照课程步骤创建或使用练习仓库，编辑 index.html 文件，补充页面标题、正文内容和简单的页面结构。之后进入仓库设置启用 GitHub Pages，选择对应的分支作为发布来源。页面生成后，我通过浏览器访问生成的网址，检查标题、正文和页面显示效果是否正确。

本次实践让我理解了版本控制和网页发布之间的联系：每一次网页内容修改都可以通过 commit 记录保存下来，发布后的页面也能够随着仓库文件更新而更新。与传统手动上传网页文件相比，GitHub Pages 更适合课程展示和小型项目展示，因为它把代码托管、版本记录和页面发布结合到一起。对我后续做机器人项目展示、课程设计说明或个人作品集都有帮助。

## 四、学习遇到的困惑与疑问（选做）
